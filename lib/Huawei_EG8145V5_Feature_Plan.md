# Huawei EG8145V5 Feature Plan

## Current stable features

- Router IP configuration
- Huawei administrator login/session
- WAN Information
- WAN name
- WAN status
- WAN IP address
- WAN VLAN ID
- WAN refresh

## Phase 1 — Dashboard/UI

Goal: make the Huawei module feel like a dedicated router-management experience rather than a test screen.

- Huawei EG8145V5 header and connection state
- WAN summary cards
- Router Management section
- Wi-Fi Settings entry
- Device Access Control entry
- Consistent loading/error states

## Phase 2 — Wi-Fi Settings

Target controls:

### 2.4 GHz
- Enable/disable WLAN if supported
- SSID name
- SSID broadcast
- Security/authentication mode
- Wi-Fi password / WPA pre-shared key
- Channel / channel mode if exposed by the firmware

### 5 GHz
- Enable/disable WLAN if supported
- SSID name
- SSID broadcast
- Security/authentication mode
- Wi-Fi password / WPA pre-shared key
- Channel / channel mode if exposed by the firmware

### Safety behavior

- Load the current settings before allowing edits.
- Show unsaved changes clearly.
- Require an explicit Save/Apply action.
- Warn that changing SSID/password can disconnect the phone running Router Manager.
- Never display or log passwords unnecessarily.

## Phase 3 — Device Access Control

Goal: manage Wi-Fi client access without requiring the user to open the Huawei web interface.

### Device list

- Connected/online devices
- Device name
- MAC address
- IP address when available
- Connection band/SSID when available
- Access state

### Access control

- Enable/disable access control
- Blacklist mode
- Whitelist mode
- Add device by selecting a known client
- Add device manually by MAC address
- Remove device from list
- Apply changes

Huawei documentation describes WLAN MAC filtering with blacklist/whitelist modes and source MAC addresses. The exact EG8145V5 firmware endpoints must still be captured/confirmed before implementing writes. Do not assume endpoints from another Huawei model.

## Phase 4 — Connected Devices

If the EG8145V5 exposes a stable authenticated client-list endpoint:

- Discover active LAN/Wi-Fi clients
- Show hostname/device name
- MAC address
- IP address
- Connection type/band if available
- Refresh
- Link to Device Access Control

## Phase 5 — Additional read-only information

Potential future items:

- WAN gateway
- DNS servers
- WAN connection type
- MAC address
- LAN information
- DHCP leases
- Optical/ONT status if exposed
- System uptime
- Firmware version

## Implementation rule

Do not guess Huawei CGI/ASP endpoints.

For every new feature:

1. Use the authenticated Huawei session already provided by `HuaweiApi`.
2. Identify the exact EG8145V5 web page used by the router.
3. Capture the browser Network request for loading the settings.
4. Capture the request generated by Apply/Save.
5. Confirm request method, path, query/body parameters, token, cookie, and response.
6. Implement the endpoint in `huawei_api.dart`.
7. Keep parsing and HTTP logic out of Flutter screens.
8. Test read-only behavior first.
9. Test writes only after the read endpoint and request format are confirmed.
10. Update this document with the confirmed endpoint and field mapping.

## Architecture

Huawei router
    -> HuaweiApi
    -> Huawei models
    -> Huawei feature screens
    -> Router Manager UI

The UI must not contain Huawei-specific JavaScript parsing, CGI paths, authentication tokens, or field indexes.
